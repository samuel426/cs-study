## 핵심 개념

| 용어 | 의미 |
|---|---|
| 가상 주소 | 프로세스가 자신의 주소 공간에서 사용하는 주소 |
| 물리 주소 | 실제 RAM의 위치를 가리키는 주소 |
| 페이지 | 가상 메모리를 일정한 크기로 나눈 조각 |
| 프레임 | 물리 메모리를 페이지와 같은 크기로 나눈 칸 |
| 페이지 테이블 | 가상 페이지와 물리 프레임의 대응 등을 기록한 구조 |
| 오프셋 | 페이지 또는 프레임의 시작에서 떨어진 거리 |
| TLB | 주소 변환 정보를 빠르게 찾도록 보관하는 작은 하드웨어 캐시 |

프로세스마다 주소 대응 관계가 다를 수 있으므로 같은 가상 주소가 반드시 같은 물리 위치를 뜻하지 않는다. 연속된 가상 페이지들도 서로 떨어진 물리 프레임에 연결할 수 있다. 이는 가상 주소와 물리 주소의 개수 차이 때문이 아니다.

이번 단순 페이징 예제에서는 페이지 번호를 프레임 번호로 변환하고 오프셋은 유지한다. 번호와 주소는 0부터 시작한다.

> 가상 주소 = 페이지 번호 × 페이지 크기 + 오프셋
>
> 물리 주소 = 프레임 번호 × 프레임 크기 + 오프셋

TLB에서 필요한 변환을 찾으면 hit, 찾지 못하면 miss다. Miss일 때 페이지 테이블에서 유효한 대응을 확인해 TLB에 보충할 수 있다. TLB에 변환 정보가 없다는 사실만으로 RAM에 데이터가 없다고 판단할 수 없다. [OSTEP 19장 · Paging: Faster Translations](https://pages.cs.wisc.edu/~remzi/OSTEP/vm-tlbs.pdf)

## 확인 문제와 피드백

### 1. 같은 순서로 락을 얻으면 B는 어디에서 기다릴까?

**질문:** A·B와 처음에 풀린 L1·L2만 있다. 둘 다 L1을 얻은 다음 L2를 얻으며 L1을 못 얻으면 L2를 먼저 잡을 수 없다. A가 L1만 얻은 직후 B가 실행되었다. B가 기다리는 락과 보유한 락은 무엇인가? 이후 A가 다시 실행되면 L2를 얻어 진행할 수 있을까? 이유도 설명해 달라.

**내 답변:** “A의 락을 기다리고 A가 L2를 놓아주기 전까지 기다려야해 / 진행가능함”

**피드백:** A가 진행할 수 있다는 결론은 맞다. B는 A가 가진 L1을 기다린다. A는 L2를 아직 얻지 않았고, B도 L1을 얻지 못해 L2를 요청하는 단계로 넘어가지 못한다. B는 가진 락이 없으므로 A가 비어 있는 L2를 얻을 수 있다. B가 L1을 얻으려면 먼저 A의 L1 해제가 필요하다. B의 보유 락과 A의 진행 이유는 직접 설명하지 않아 보완했다. 지난 수업에 이어 락 순서의 실행 흐름은 복습 대상으로 남긴다.

### 2. 서로 다른 프로세스의 같은 가상 주소는 같은 물리 위치일까?

**질문:** 서로 다른 프로세스인 메모장과 브라우저가 각각 가상 주소 1000에 접근했다. 주소 숫자가 같으니 반드시 RAM의 같은 위치를 읽는다고 할 수 있을까? 가상 주소·물리 주소의 관계로 이유를 설명해 달라.

**내 답변:** “아닐거 같은데 가상 주소는 적고 물리주소는 가상주소에 비해 많아서 약간 어떤 설정에 따라 다를거 같은데 그걸 모르겠네”

**피드백:** 반드시 같은 위치가 아니라는 결론은 맞다. 이유는 주소의 개수 차이가 아니라 프로세스마다 주소 대응 관계가 다를 수 있기 때문이다. 사용자가 추측한 “설정”을 페이지 테이블이라는 구체적인 구조로 연결했다. 이 이유를 사용자가 직접 설명한 것으로 기록하지 않는다.

**설명 예시의 범위:** 대화에서 가상 주소 1000이 각각 물리 주소 5000과 9000에 연결되는 예를 들었다. 이는 주소 대응의 차이를 보여 주는 개념적 예이며 특정 페이지 크기의 페이징 계산 예제가 아니다. 아래 문제 4에서는 페이지 크기·매핑을 명시하고 오프셋을 유지해 계산했다.

### 3. 연속된 가상 페이지가 RAM에서는 떨어져 있어도 될까?

**질문:** 페이지와 프레임의 크기는 모두 같고 두 페이지 모두 RAM에 있다. 페이지 테이블에서 가상 페이지 0은 물리 프레임 5에, 가상 페이지 1은 물리 프레임 9에 연결된다. 프로그램에서는 연속된 페이지가 RAM에서는 떨어져 있어도 사용할 수 있을까? 페이지 테이블의 역할과 연결해 설명해 달라.

**내 답변:** “사용할 수 있을거 같아 가상 페이지의 역할이 물리 페이지의 위치를 찾아주는 역할을 하거든”

**피드백:** 사용할 수 있다는 판단과 위치 대응을 이용한다는 방향은 맞다. 다만 대응 정보를 담는 구조는 가상 페이지 자체가 아니라 페이지 테이블이다. 가상 페이지는 메모리 조각이고 페이지 테이블이 0→5, 1→9의 연결 정보를 제공한다. 페이지와 페이지 테이블의 용어 구분은 설명으로 보완했다.

### 4. 가상 주소를 페이지 번호·오프셋으로 나누고 물리 주소를 구해 보자

**질문:** 계산용 가상 시스템에서 페이지와 프레임 크기는 모두 16바이트이고 주소·번호는 0부터 시작한다. 가상 페이지 2는 물리 프레임 7에 연결되며, 해당 페이지는 RAM에 있고 접근도 허용된다. 가상 주소 38의 페이지 번호, 오프셋, 최종 물리 주소와 계산 과정은?

**내 답변:** “페이지 번호는 3 오프셋은 6 물리주소는 모르겠어”

**피드백:** 오프셋 6은 맞다. 주소 38은 세 번째 페이지에 속하지만 0부터 세므로 페이지 번호는 2다. 페이지 0은 주소 0~15, 페이지 1은 16~31, 페이지 2는 32~47이다.

- 38 = 2 × 16 + 6 → 페이지 번호 2, 오프셋 6.
- 페이지 테이블의 대응: 페이지 2 → 프레임 7.
- 프레임 7의 시작 주소는 7 × 16 = 112.
- 최종 물리 주소는 112 + 6 = **118**.

페이지 번호와 물리 주소 계산은 보충 설명이며 아직 다시 풀어 확인하지 않았다. 오프셋 값은 사용자가 맞혔다.

### 5. TLB miss가 나면 데이터를 디스크에서 다시 가져와야 할까?

**질문:** TLB에 페이지 2의 변환 정보가 없다. 페이지 테이블에는 페이지 2→프레임 7이 기록되어 있고, 해당 데이터는 이미 RAM에 있으며 접근 권한도 문제없다. TLB miss라는 이유로 데이터를 디스크에서 다시 가져와야 할까? 다음에 어떤 표를 확인하면 되는지와 이유를 설명해 달라.

**내 답변:** “그럴 필요는 없고 페이지 테이블 찾아보면 될거 같은데 기록되어 있으니까”

**피드백:** 결론과 다음 확인 대상 모두 맞다. 페이지 테이블에서 변환을 확인할 수 있고 데이터도 이미 RAM에 있으므로 디스크에서 다시 가져올 필요가 없다. TLB miss는 주소 변환 캐시에 정보가 없다는 뜻이며 RAM에 데이터가 없다는 뜻이 아니다. 이번 사례의 판단은 답변으로 확인했다. 페이지 폴트의 종류와 처리 과정은 다음 수업에서 다룬다.

## 보완한 생각과 복습 포인트

- 같은 가상 주소가 반드시 같은 물리 위치는 아니라는 결론은 확인했다. 프로세스별 대응 관계라는 이유는 다시 설명해 보아야 한다.
- 떨어진 물리 프레임도 사용할 수 있다는 판단과 대응 정보를 이용한다는 방향은 확인했다. 페이지·프레임·페이지 테이블은 구분해 복습한다.
- 오프셋 6은 맞혔지만 0부터 세는 페이지 번호와 물리 주소 계산은 다음 수업에서 먼저 복습한다.
- TLB miss 사례에서 페이지 테이블을 확인하고 디스크 재조회가 불필요하다는 판단은 확인했다. ASID나 모든 페이지 폴트 상황까지 이해했다고 확대하지 않는다.
- 락 순서 통일 예제에서 B의 보유 락과 대기 위치는 여전히 복습이 필요하다. permit 획득·반환, 에이징, 0이 아닌 도착 시각의 응답 시간 계산도 이전 복습 목록에 유지한다.
